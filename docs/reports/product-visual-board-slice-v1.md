## Зоны — содержание (плейсхолдеры «после гипотезы»)

### 1. Кто / работа

**Фиксировано в срезе (не редактируется на первом тесте):**

- **Кто:** основатели и соло-операторы цифровых продуктов.
- **Работа:** готовое пространство — не искать фреймворки с нуля; усилить навыки в паре с ИИ.
- **Формат:** kit = Notion OS (UI для людей) + Git-копия (правки с агентом).
- **ИИ:** опционально; проверять и править, не отдавать на автопилот.

*Источник:* [`docs/positioning.md`](../positioning.md)

### 2. Срез сейчас

**Фиксировано:**

| Поле | Значение |
|------|----------|
| Продукт | Small Business Space v1.0 [RU] |
| Тип | Шаблон / digital product kit |
| Не | SaaS, не лендинг, не маркетинг-стратегия Prod.Swaim |
| Состояние | Foundation A–D ✅; Other ✅; следующая группа — выбор владельца |

**После гипотезы:** одна строка «что в фокусе этой недели» (outcome, не список фич).

### 3. Гипотезы (≤3)

**Структура строки:**

`[ID] Мы верим, что … → если …, то [сигнал] · Статус: не проверена | в проверке | подтверждена | опровергнута`

**Сейчас:** три пустые строки с подписью `[после гипотезы]`.

*Школа:* Ries — явная гипотеза; WIP ≤3 (Lean).

### 4. Сигнал

**После гипотезы заполняется одним блоком:**

- Поведение в прошлом (Mom Test) **или** обязательство (время / деньги / публичный шаг).
- Не vanity: не «нравится», не «скачали PDF».

**Пустое состояние:** «Сигнал появится после выбора гипотезы для проверки».

### 5. Следующий шаг — один

**Правило:** ровно одно действие, связанное с активной гипотезой или сигналом.

**Пустое состояние:** «Один шаг — после приоритизации гипотезы».

## Пустые / error states (только этот срез)

| Ситуация | Что видит читатель |
|----------|-------------------|
| Гипотезы не заданы | Зона 3: три строки-заглушки + подсказка формата |
| Нет сигнала | Зона 4: серая подпись «после гипотезы» |
| Нет шага | Зона 5: «один шаг — после приоритизации» |
| Перегруз (>3 гипотез) | **Не показывать** — WIP-лимит на уровне процесса |

## Acceptance Criteria

### UX (этот артефакт)

- [ ] **AC-1:** За ≤2 сек читатель называет: *кто*, *что за продукт сейчас*, *сколько гипотез*, *есть ли сигнал*, *какой один шаг*.
- [ ] **AC-2:** Пять зон видны без скролла на экране ≥1280×800 (FigJam frame) или на одной markdown-странице.
- [ ] **AC-3:** Зоны 3–5 явно помечены «после гипотезы» — не выдают фиктивную заполненность.
- [ ] **AC-4:** После теста команда **редактирует** зоны 2–5, не перерисовывает зону 1 и каркас.

### FigJam (handoff → FoundingEngineer / владелец)

- [ ] **AC-5:** Один FigJam-фрейм «Product Visual Board — slice v1» с 5 sticky-зонами по макету выше.
- [ ] **AC-6:** Ссылка на FigJam — в комментарии SWA-9 и в SWA-8.

---

## Как поймём (тест)

**Кто:** ProductOwner или владелец (30 сек, без подсказок).  
**Действие:** показать макет (FigJam или этот md) → спросить: «Что мы строим, для кого, что проверяем, что дальше?»  
**Pass:** 4/5 зон названы верно без «это Notion-шаблон для всех подряд».  
**Fail:** путают с SaaS / просят «добавить всё остальное» → срез раздут, вернуть WIP.

## Остаточный риск

- **Usable:** без FigJam-рендера founder может не почувствовать «одну картину» — нужен 30-сек тест.
- **Scope creep:** давление «добавить все модули v1» — отклонять, ссылаться на WIP ≤3.
