# Paperclip: только ПК владельца («локально»)

Канон для агента и владельца. Дополняет [`AGENTS.md`](../AGENTS.md).

## Жёсткое правило (агент)

| Фраза владельца | Что делать | Чего **не** делать |
|-----------------|------------|---------------------|
| «локально», «на моём ПК / компьютере», «у себя» | Дать команды для **машины владельца**; ждать его подтверждения, что UI открыт **без** Cloud Agent port forward | Ставить / `onboard` / `run` Paperclip на **Cloud Agent VM** и называть это «локальной установкой» |
| «на VM / в этом чате / на агенте» | Можно трогать Paperclip **только** на текущей Cloud Agent VM — и **явно** сказать, что данные на VM | Молча подменять «локально» туннелем `127.0.0.1` → VM |

**Cloud Agent VM ≠ компьютер владельца.**  
`http://127.0.0.1:3100` в браузере владельца при открытом Port Forward Cursor часто указывает на **VM агента**, не на Windows. Это выглядит «локально», но данные лежат на диске VM и пропадут с окружением.

Если владелец сказал «локально», а агент уже крутит Paperclip на VM — **остановиться**, объяснить путаницу, предложить переход на ПК. Не продолжать наращивать «локальный» setup на VM без явного «ок, пока на VM».

## Целевое развёртывание (с 2026-08-16)

- **Рабочий Paperclip** = инстанс на **ПК владельца** (Windows).
- Инстанс на Cloud Agent VM — **лаборатория / черновик**, не source of truth. Данные с VM **не переносятся автоматически** на ПК.

## Чеклист: поднять Paperclip на ПК владельца

Владелец выполняет у себя в терминале (Node.js установлен):

```bash
npx paperclipai onboard
# или, если конфиг уже есть:
npx paperclipai run
```

Рекомендуемые ответы мастера (как договаривались):

1. Режим: **authenticated** / private / loopback  
2. UI: `http://127.0.0.1:3100` — **без** Port Forward из Cloud Agent  
3. Secrets → секрет (имя может быть `cursor_key`)  
4. У агентов Cursor Cloud: env **NAME** = `CURSOR_API_KEY`, **VALUE** = этот секрет  
5. `repoUrl` = `https://github.com/vikiswaimer/Prod.Swaim.com`  
6. Модель: Default / auto  
7. Не будить всю команду сразу (лимит Cursor Cloud ~8); heartbeat off / wake on demand  
8. После run — disposition issue: `done` / `in_review` / `blocked`

## Что агент может делать из Cloud-чата

| Можно | Нельзя (без явной просьбы «на VM») |
|-------|-------------------------------------|
| Писать/править эту инструкцию и чеклисты в `docs/` | `npx paperclipai onboard/run` на VM «как локально» |
| Подсказывать команды для ПК владельца | Утверждать, что port-forward UI = локальный ПК |
| Разбирать скрины / логи, которые прислал владелец | Считать данные VM перенесёнными на ПК |

## История ошибки (не повторять)

В чате Paperclip Cloud Agent агент развернул Paperclip на **VM**, владелец открывал `127.0.0.1:3100` через туннель и считал это установкой на свой ПК. Отсюда `ERR_FAILED` при обрыве forward и путаница с «сессией». Решение владельца: **перейти на ПК**; правило выше — чтобы агент больше так не подменял «локально».
