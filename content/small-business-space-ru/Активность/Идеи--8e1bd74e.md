# Идеи (банк идей)

Это **банк идей**, а не склад фантазий. Сюда кладёте сырые мысли, превращаете сильные в **гипотезы** и решаете: проверить сейчас / отложить / отбросить.

Идея без способа проверки и сигнала успеха — шум. Высокий «балл влияния» без фактов — тоже шум.

<aside>
Банк идей живёт здесь (Notion). Исполнение проверки — лучше в трекере задач с ИИ: Linear или GitHub Issues. В карточке идеи держите ссылку на issue/эксперимент.
</aside>

---

## Зачем это в шаблоне продукта

1. **Не потерять** мысли, которые мелькнули после интервью или поддержки.
2. **Не распылиться** — в работе только то, что связано с целью и риском обучения.
3. **Закрыть цикл Lean:** гипотеза → дешёвый тест → вывод → next step.

Исход раздела: вы всегда можете сказать, какие 1–3 идеи сейчас в проверке и что будет считаться успехом.

---

## Как устроен поток

```text
Сырая заметка → формулировка гипотезы → к проверке → в работе (эксперимент)
                                              ↓
                                    вывод (learned) → next step
                                    или отложить / отбросить
```

| Статус | Смысл |
|--------|--------|
| Сырая | Ещё мысль; нет гипотезы |
| Уточнить | Нужны факты / интервью, прежде чем тест |
| К проверке | Гипотеза и способ проверки ясны; ждёт слота WIP |
| В работе | Идёт эксперимент (есть задача / issue) |
| Вывод | Есть обучение: подтверждена / опровергнута / уточнить |
| Отложена | Не сейчас; причина коротко |
| Отброшена | Явно нет — чтобы не всплывала снова |

Статусы «К проверке / В работе / Вывод» ≈ To learn / Doing / Learned.

## Формула гипотезы

Кратко в карточке:

> Верим, что **[кто]** сталкивается с **[проблемой]**.  
> Если дадим **[решение / срез]**, то **[поведение или метрика]** за **[срок]**.

Плохо: «Сделаем тёмную тему — всем понравится».  
Лучше: «Верим, что фрилансеры бросают онбординг из‑за длинной формы. Если сократим до 3 полей, активация за 7 дней вырастет с 20% до 35%».

Разговор с рынком — про **их жизнь и прошлое**, не «купили бы вы…» (см. Интервью / Отзывы в Дополнительно).

---

## Поля карточки (минимум)

| Поле | Смысл |
|------|--------|
| Гипотеза | Формула выше |
| Как проверим | Самый дешёвый честный тест за N дней |
| Сигнал успеха | Что увидим: метрика, поведение, обязательство |
| Статус | Из таблицы выше |
| Вывод | Что узнали |
| Next step | Что делаем после вывода |
| Ссылка наружу | Issue в Linear / GitHub (если исполнение там) |
| Доверие / Выполняемость / Влияние | Вторичный приоритезатор (0–…); не замена гипотезы |
| Баллы | Ориентир порядка; высокий балл ≠ «делать сразу» |

---

## Где вести проверку гипотез

| Место | Роль |
|-------|------|
| **Эта база (Notion)** | Банк, приоритизация, формулировки, выводы для себя и команды в пространстве |
| **Linear** | Предпочтительно для продукта с ИИ: циклы, статусы, агенты, чистый WIP |
| **GitHub Issues** | Если код и агент уже в репозитории; issue = эксперимент или поставка |
| База [Задачи](Задачи--c110a4ad.md) здесь | Лёгкий WIP, если отдельный трекер ещё не нужен |

Не дублируйте одно и то же в трёх местах. Правило: **одна карточка-истина для смысла (здесь) + одно место исполнения (Linear/GitHub/Задачи)**.
