## Что это за продукт

**Prod.Swaim / Small Business Space v.1.0 [RU]** — шаблон (digital product kit) для управления и развития цифровых продуктов / малого бизнеса.

Ценность для пользователя:
- готовые решения «не искать и не думать с нуля» под типовые ситуации;
- можно работать без ИИ или **в паре с ИИ**, проверяя и усиливая навыки;
- основной UX для людей сейчас в **Notion**; Git — рабочая копия для правок с агентом / Issues / (опционально) Obsidian.

## Как работать по задачам

1. **Один чат = одна группа** (например Other, Клиенты, Активность) **+ диалог** с владельцем. Гипотезы правок согласовывать в разговоре и адаптировать — не гнать сквозной «пакетный» план.
2. **Один чат = один GitHub Issue** (по умолчанию). Scope = эта группа / выбранные блоки; одна ветка / один draft PR.
3. **Не дробить** чат на несколько issues/PR и **не тащить соседние группы**, пока владелец явно не попросит.
4. Правки в `content/**` (и при необходимости `docs/**`).
5. Ветки: по умолчанию `cursor/<short-name>-ffef` + draft PR. Если пользователь явно сказал «можно в main» — можно коммитить в `main`.
6. В issue/PR указывать: что перенести в Notion вручную (особенно DB schema / views / формулы).
7. Не трогать лендинг и маркетинговую стратегию, пока нет отдельного issue/чата.

## Контент для людей (Notion / шаблон)

- **Не вставляйте** в пользовательские страницы шаблона голые ссылки на GitHub, `docs/*.md` репозитория и внутренние тикеты («см. пакет D», «см. methodology.md»).
- Про работу с ИИ и копией файлов пишите **развёрнуто в Instructions**, без вырванных URL.
- Допускается мягкая рекомендация: скачать/подключить копию шаблона к ИИ-агенту и разобрать разделы — без обязательной ссылки на конкретный хостинг.

## Ограничения экспорта Notion → Git

- Нет галерей, board, calendar UI, сложных linked views.
- Базы = CSV (+ md страницы записей).
- Имена файлов **укорочены** (лимит пути ОС); суффикс `--xxxxxxxx` = короткий hash id Notion.
- Внутренние ссылки уже чинились (см. `00-index.md` / `INDEX.md`). При переименованиях — обновлять ссылки.
- Карта старых→новых путей: `docs/notion-export-path-map-full.json`.

Повторный импорт из zip затирает правки в `content/` — делать только осознанно и в отдельной ветке.

## Быстрый старт агента в новом чате

1. Прочитать `AGENTS.md` + **`docs/methodology.md`** + `docs/agent-context.md`. `roadmap-v2.md` — только как справка, не как скрипт исполнения.
2. Уточнить у владельца **какую группу/блоки** делаем в этом чате; вести диалог (гипотеза → правка → проверка), не закрывать «весь v2».
3. Привязать чат к **одному** GitHub Issue под эту группу. Не открывать второй issue и не смешивать группы без явной просьбы.
4. Смотреть файлы через `00-index.md` / `INDEX.md`, не через «сырой» zip.
5. Править в духе методологии; минимальный diff под согласованный scope.
6. В конце: commit/push, обновить **этот** issue, кратко по-русски что сделано, что перенести в Notion.
