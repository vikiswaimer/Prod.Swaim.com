# Чеклист поставки Git → Notion (для команды)

**Кому:** Delivery Engineer, агенты, владелец при ручном переносе.  
**Не для:** страниц шаблона, которые видит покупатель (туда этот документ не копируем).

Канон подключения и скриптов: [`notion-integration.md`](notion-integration.md).  
ZIP целиком **не** используем: [`notion-reimport.md`](notion-reimport.md).

---

## 1. Зачем этот чеклист

Git (`content/small-business-space-ru/`) — рабочая копия для правок с агентом.  
Notion — UI для людей. Поставка = довести **согласованный срез** из Git в живую копию шаблона так, чтобы:

- текст и смысл совпали с Git;
- схемы баз / views / формулы либо обновлены, либо явно отложены с владельцем;
- ничего лишнего не затёрто (соседние прогоны, чужие DB, демо, которое решили оставить).

Исход поставки: владелец (или следующий агент) за минуту понимает, **что уже в Notion**, а **что руками**.

---

## 2. Перед стартом (gate)

Отметьте перед любой записью в Notion:

- [ ] Scope = **один** issue / одна группа чата; соседние группы не тащим.
- [ ] Ветка / PR известны; diff по `content/**` (и при необходимости `docs/reports/**`) просмотрен.
- [ ] В пользовательских страницах шаблона **нет** ссылок на GitHub, `docs/*.md`, внутренние тикеты («см. пакет D»).
- [ ] Внутренние markdown-ссылки в Git не битые (скрипт из [`agent-context.md`](agent-context.md)).
- [ ] Выбран канал поставки (таблица ниже) и **корень** живой копии SBS (не чужой workspace).
- [ ] Если живую копию уже трогал другой прогон — **не** перезаписывать молча; сверка / сравнение / ручной merge (см. [`reports/notion-sync-business-compare.md`](reports/notion-sync-business-compare.md)).

| Канал | Когда | Картинки | Риски |
|-------|--------|----------|--------|
| **A. Notion MCP** (Desktop) | Точечный текст, живой чат | Нет через MCP | Нужен OAuth; headless Cloud Agent неудобен |
| **B. `NOTION_TOKEN` + скрипты** | Cloud Agent, пилот sync, пакетные страницы | File Upload API | Затирает блоки страницы — только осознанный `--apply` |
| **C. Вручную по чеклисту** | Нет токена / сложные views / формулы / сравнение прогонов | Вставка в UI | Долго, но безопасно для layout |

Smoke перед API:

```bash
python3 scripts/notion_smoke.py
```

Карта страниц **вашей** копии SBS: [`reports/notion-sbs-page-map.json`](reports/notion-sbs-page-map.json).  
Не резолвить ссылки «по всему workspace» — только по этой карте (или обновлённой после `notion_inspect`).

## 3. Классификация изменений → что делать в Notion

Для каждого файла / сущности в diff поставьте тип и действие:

| Тип в Git | В Notion | Авто (скрипт/MCP) | Всегда руками в UI |
|-----------|----------|-------------------|-------------------|
| Текст хаба / гайда (`.md`) | Та же страница (по title / page_id) | Да, точечно | Проверить callout, toggles, linked mentions |
| `examples/*.md` | Отдельная страница или toggle «Пример» | По желанию | Не смешивать с чистым шаблоном |
| CSV = схема свойств | Properties DB | Частично / осторожно | Select-опции, формулы, rollup, relations |
| CSV = демо-строки | Rows | Редко | Пометить «пример» / удалить шум |
| Новая страница | Create + parent | Да | Иконка, cover, порядок в parent |
| Переименование | Title + ссылки | Title — да | Обновить linked databases / mentions |
| Views (board, calendar, gallery, filters) | Views | **Нет** (API ограничен) | Создать/поправить в UI |
| Картинки / иконки callout | Image blocks / upload | Способ B | File-icon на callout API **не** ставит — emoji или картинка внутри |

## 4. Пошаговая поставка (рабочий цикл)

### Шаг A — Собрать манифест поставки

В issue / PR / комментарии агента заполните блок (можно копировать):

```markdown
## Поставка Git → Notion

**Issue:** …
**Ветка / PR:** …
**Корень SBS page_id:** …
**Канал:** MCP / API / вручную

### В эту поставку
| Git-путь | Notion page / DB | Действие | Статус |
|----------|------------------|----------|--------|
| content/.../Foo.md | Foo (`…-id`) | заменить текст | pending |

### Руками в UI после текста
- [ ] …
- [ ] Views / формулы: …

### Не трогаем
- …

### Проверка
- [ ] Открыл 2–3 ключевые страницы в Notion — смысл = Git
- [ ] Нет GitHub/`docs/` в пользовательском тексте
- [ ] Внутренние ссылки ведут на страницы **этой** копии SBS
```

### Шаг B — Dry-run (если API)

```bash
# пример пилота одной страницы
python3 scripts/notion_sync_pilot.py \
  --page-id <ID> \
  --md content/small-business-space-ru/<path>.md \
  --assets-dir content/small-business-space-ru/<dir> \
  # без --apply = dry-run
```

Пакетные скрипты (если есть под задачу): `notion_sync_pack_d.py`, и т.п. — сначала `--dry-run` / без `--apply`.

### Шаг C — Apply / ручной перенос

- [ ] Писать **по страницам из манифеста**, не «весь космос».
- [ ] После каждой критичной страницы — быстрый взгляд в UI.
- [ ] Картинки: не дублировать огромные icon-children в callout (см. пилот).
- [ ] DB: сначала properties, потом демо-строки; views — отдельным пунктом «руками».

### Шаг D — Закрытие поставки

- [ ] Манифест: все строки `done` / `skipped` с причиной.
- [ ] Короткий отчёт в `docs/reports/` (если поставка нетривиальная) **или** достаточный комментарий в issue.
- [ ] В PR: секция «Что перенести / что уже в Notion».
- [ ] Issue: статус + ссылка на отчёт / page_id.

## 5. Мини-чеклист по типу страницы

### Хаб раздела (Клиенты, Other, …)

- [ ] Заголовок и intro совпадают с Git.
- [ ] «Место в разделе» / маршрут — если меняли в Git.
- [ ] Ссылки на дочерние страницы = page_id из карты SBS.
- [ ] Нет внутренних ссылок на `docs/` и GitHub.

### Трек Быстрый старт (чеклист to_do)

- [ ] Пункты to_do и checked-состояние осознанны (шаблон обычно unchecked).
- [ ] Linked page mentions на модули живые.

### База (CSV ↔ DB)

- [ ] Список свойств = CSV-заголовки (или явный diff схемы в манифесте).
- [ ] Select/multi-select: все опции из шаблона.
- [ ] Формулы: перенести текст формулы; прогнать 1 smoke-строку.
- [ ] Views: имена + фильтры из отчёта пакета; API не заменяет UI.
- [ ] Демо-записи: помечены как пример или удалены.

### Instructions / позиционирование

- [ ] Блоки «для кого», «с ИИ», indications — без отсылок к репо.
- [ ] Callout: emoji вместо file-icon, если шли через API.

---

## 6. Красные флаги (стоп)

Остановите поставку и уточните у владельца, если:

- Diff затрагивает **две+ группы** без явного разрешения.
- В живой копии уже есть параллельный прогон (сравнение / чужие page_id).
- Нужен **массовый** recreate DB с production-данными пользователя (не шаблон).
- Предлагают снова **ZIP-импорт** всего пространства.
- В текст шаблона просятся URL GitHub / `methodology.md` / номера внутренних тикетов.

## 8. Definition of Done (поставка)

Поставка закрыта, когда:

1. Манифест заполнен и статусы проставлены.
2. Ключевые страницы из scope в Notion соответствуют Git по смыслу.
3. Пункты «руками в UI» либо сделаны, либо явно перенесены владельцу с приоритетом.
4. В пользовательском тексте шаблона нет внутренних URL репозитория.
5. Issue / PR обновлены по-русски: что сделано, что осталось в Notion UI.
